# Hunt Evidence-First Intelligence Architecture

## Purpose

Hunt is an evidence and change-detection system for company intelligence.

It must not manufacture commercial findings from hardcoded category rules.

The core boundary is:

```
public source
  -> observation
  -> evidence/provenance
  -> state/version
  -> observed change
  -> correlated evidence
  -> investigation input
  -> external AI/user interpretation
  -> commercial action
```

Hunt owns the first half. External intelligence owns the interpretation.

## Evidence is not a finding

An observation says what Hunt actually encountered.

Examples:

- A job posting exists at a source URL.
- A regulator page references a company.
- A public API surface is reachable.
- A person appears on an official company page.
- A certificate for a subdomain was observed.
- A procurement notice contains the company name.

A finding is an interpretation across evidence.

Examples of findings that Hunt must **not** hardcode:

- "The company needs cybersecurity services."
- "The company is about to raise funding."
- "The company needs backend engineers."
- "This is a sales opportunity."

Those are investigation questions for an external AI/user.

## Required provenance

Every durable observation should preserve, where available:

- company/entity
- source
- source URL
- source tier
- observed timestamp
- first/last seen
- evidence type
- verification status
- entity confidence
- evidence confidence
- source-specific metadata
- stable identity/fingerprint
- current state
- disappearance/restoration state

Evidence should remain inspectable back to the originating source.

## State versus event

Current state is useful for queries, but historical change must remain reconstructable.

For mutable surfaces, use a stable identity and compare snapshots.

For example:

```
website|example.com
  snapshot A -> content hash A
  snapshot B -> content hash B
  snapshot C -> content hash C
```

The identity remains the same while the observed content changes.

A change should therefore mean a meaningful difference in the observed evidence, not merely a new URL/hash generated by the collector.

## Correlation

Signal clusters must correlate independent evidence within a defined time window.

A cluster should consider:

- temporal proximity
- signal-family diversity
- source diversity
- evidence freshness
- whether observations are genuinely new/changed
- whether sources are independent
- contradictions or missing evidence

Repeated copies of the same source must not masquerade as independent corroboration.

## Commercial interpretation boundary

Hunt may calculate deterministic evidence-quality and relevance metadata.

Hunt may say:

> "Three independent public observations changed within 14 days."

Hunt may not say:

> "Therefore this company needs your service."

The external investigation layer receives the evidence bundle and answers the commercial question.

## Uncertainty

These states must remain distinct:

- verified
- reachable
- unverified
- unknown
- suspected missing
- confirmed removed
- restored
- contradicted
- needs review

Unknown must never silently become verified.

## Entity resolution

A company is a canonical entity, not merely a search string.

Future identity resolution should preserve:

- canonical name
- aliases
- official domains
- legal identifiers
- regulator identifiers
- subsidiaries/relationships
- source-specific identities
- identity confidence

Wrong attribution is worse than missing evidence.

## Financial evidence

Financial extraction is evidence collection, not truth creation.

A financial value should preserve:

- metric
- value
- unit
- currency
- period
- statement type
- source
- source URL
- source publication date
- extraction context
- verification status
- confidence

Extraction must be allowed to abstain or require admin review.

## External AI contract

The external AI should be able to request:

1. company identity
2. current state
3. recent changes
4. evidence records
5. source URLs
6. evidence excerpts/locators where available
7. confidence and verification state
8. contradictions and missing evidence
9. correlated evidence windows
10. prior investigation state

It should never have to trust a Hunt-generated sentence without being able to inspect the evidence behind it.

## Product principle

Hunt's strongest output is not:

> "Here is the opportunity."

It is:

> "Here is what changed, when it changed, what public evidence supports it, how strong that evidence is, what else changed around the same time, and what remains unknown."

That is the foundation on which an external AI can safely reason about commercial opportunity.
